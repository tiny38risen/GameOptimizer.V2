# 0003. 보조 코어는 지배 코어와 같은 L3에서 고른다

- 날짜: 2026-11-16
- 결정: 지영

## 문제

지배 스레드를 뺀 나머지 게임 스레드(오디오, 입력 등)는 보조 코어 하나에 모읍니다. 이 스레드들의 부하는 합쳐도 약 2%라서, 속도보다 방해가 적은 코어가 중요합니다. "같은 L3를 공유하는 서로 다른 물리 코어 두 개"는 v3를 처음 구상할 때부터 넣은 조건이고, 실측 로그를 보고 보조 코어 기준을 보완할 때도 이 조건은 유지했습니다.

## 선택지

| | 내용 |
|---|---|
| A (선택) | 지배 코어와 같은 L3를 쓰는 코어 중에서, 인터럽트·DPC가 가장 적은 코어 |
| B | L3와 관계없이 인터럽트·DPC가 가장 적은 코어 |

## 결정

A. 그리고 지배 코어를 고르기 **전에**, 후보 코어가 2개 이상인 L3 묶음만 남깁니다. 지배 코어를 먼저 고르면 그 L3에 보조 코어가 없어서 선정이 실패할 수 있기 때문입니다.

## 이유

지배 스레드와 나머지 스레드는 게임 상태, 오디오 버퍼, 입력 이벤트, 동기화용 잠금을 계속 주고받습니다.

- 같은 L3: 한쪽이 쓴 데이터를 다른 쪽이 공유 L3에서 바로 읽습니다.
- 다른 L3: 상대 쪽 캐시에 있는 데이터를 L3 사이의 연결(AMD 라이젠은 Infinity Fabric)을 거쳐 가져와야 해서 지연이 몇 배 길어집니다.

보조 스레드의 부하는 2%뿐이어도, 잠금을 넘겨주거나 스레드를 깨울 때마다 이 지연이 쌓여 지배 스레드가 기다리는 시간이 늘어납니다. 그래서 보조 코어는 "가장 조용한 코어"보다 "지배 코어와 데이터를 빨리 주고받을 수 있는 코어"가 먼저입니다.

## 결과

- `native/CoreSelection.cpp`의 L3 선필터와 보조 코어 조건으로 구현했습니다.
- 테스트: `SkipsL3GroupsWithOneCore`, `WorkerSharesDominantL3`(`native/tests/CoreSelectionTests.cpp`).
- L3가 두 묶음인 Ryzen 8코어 16스레드 실측 로그에서 지배 코어와 보조 코어는 매번 같은 L3였습니다(`native/tests/fixtures/ryzen-*`).
