# 0004. 지배 코어 전체를 다른 프로그램에서 비우고, 권한 없는 프로그램은 건너뛴다

- 날짜: 2026-11
- 결정: 지영

## 문제

V2는 게임이 쓰는 논리 CPU만 다른 프로그램에서 비웠습니다. 그러면 밀려난 프로그램이 같은 물리 코어의 다른 논리 CPU(SMT 형제)로 몰려서, 지배 스레드와 코어 자원을 나눠 쓰게 됩니다.

## 선택지

| | 다른 프로그램을 빼는 범위 | 남는 문제 |
|---|---|---|
| A | V2처럼 게임 논리 CPU만 | 지배 코어의 형제 논리 CPU에 다른 프로그램이 몰림 |
| B (선택) | 지배 물리 코어의 모든 논리 CPU + 보조 논리 CPU | 다른 프로그램이 쓸 CPU가 줄어듦 |

권한 없는 프로그램(보호 프로세스, Windows 중요 프로세스)은 강제로 바꾸려 하거나 실패로 처리하는 대신 건너뜁니다.

## 결정

B. 당시 결정: "지배 코어는 지금 실행 중인 다른 프로세스의 선호에서 빼는 걸로 하고, 권한이 없는 프로그램은 넘겨."

## 이유

- **물리 코어 전체:** SMT 형제 논리 CPU는 실행 유닛과 캐시를 지배 스레드와 나눠 씁니다. 형제 쪽에 다른 프로그램이 돌면 지배 스레드가 그만큼 느려지는데, 이 게임은 지배 스레드 하나가 성능을 정하므로 그 손해가 그대로 프레임에 나타납니다.
- **CPU가 적은 PC:** 논리 CPU가 적은 PC를 위해 "다른 프로그램용 CPU를 최소 2개 남기자"는 제안도 검토했지만 넣지 않았습니다. SMT가 없는 CPU에서는 비우는 범위가 게임 범위와 같아져 V2와 똑같이 동작하고, CPU가 적은 PC는 비우지 않아도 부족한 건 마찬가지이며, 게임이 쓸 코어는 부하가 낮은 곳으로 고르니 밀려나는 부하도 작기 때문입니다. 남는 CPU가 0개일 때만 적용하지 않습니다.
- **권한 없는 프로그램:** 보호 프로세스와 Windows 중요 프로세스는 관리자 권한으로도 바꿀 수 없거나 바꾸면 안 되는 대상입니다. 이것 때문에 전체 적용을 실패시키면 게임 쪽 이득까지 잃으므로, V2와 같이 건너뛰고 화면에 알리기로 했습니다.

## 결과

- 2026-11-18 실측 17회에서 지배 논리 CPU에 남은 다른 부하는 0~1.5%였습니다.
- 한계: 물리 코어가 2개인 PC에서는 다른 프로그램이 쓸 논리 CPU가 1개만 남습니다. Pentium G4560 21회 실행 중 1회는 그 논리 CPU가 포화돼 지배 코어까지 부하가 넘쳤습니다(지배 스레드 91.3%).
- 건너뛴 프로그램은 개수와 예시 3개를 화면에 알려 줍니다.
- 2코어 4스레드 PC(G4560)에서 다른 프로그램용 CPU가 1개만 남는 경계 사례를 확인했지만, 게임이 잘 실행되고 다른 프로그램을 같이 쓰지 않는 환경이라 현재 방식을 유지했습니다.
