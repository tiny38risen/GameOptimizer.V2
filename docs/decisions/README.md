## AI 활용 방식

> ✏️ **직접 작성:** 아래는 초안입니다. 실제와 다르면 고쳐 주세요.

설계 검토와 구현은 Claude(AI)와 대화하며 진행했습니다. 선택지 정리, 코드 작성, 문서 초안은 AI가 맡았고, 어떤 선택지를 쓸지와 실기 검증은 제가 했습니다.

AI의 제안을 받아들이지 않거나 고친 사례:

> ✏️ **직접 확인:** 지난 대화 기록에서 찾은 후보입니다. 맞는 것만 남기고, 기억나는 사례가 있으면 더해 주세요.

1. **목표를 다시 설명해 방향을 바로잡음.** AI는 처음에 게임을 코어 하나에 모으는 방향을 권하지 않았습니다. 이 프로젝트의 대상이 스레드 하나가 일을 거의 다 하는 게임이라는 점을 다시 설명해서 설계 방향을 바꿨습니다.
2. **SMT 없는 CPU에서의 누락을 짚음.** 4코어 4스레드 PC에서는 지배 코어 전체를 비워도 결과가 게임 범위와 같아진다는 점을 AI가 놓친 것을 지적했습니다.
3. **보조 코어의 L3 조건을 지킴.** 보조 코어 기준을 손보는 과정에서 같은 L3 조건은 유지해야 한다고 못박았습니다([0003](0003-worker-core-shares-l3.md)).
4. **명세를 더 줄이게 함.** "지금 요구사항을 위한 최소한의 구현이 맞는지" 다시 물어서, 명세에서 필요 없는 구조 4곳(별도 일정 클래스, 쓸모없는 카운터 값 등)을 걷어냈습니다.
