# 성능 측정 원자료

GameOptimizer 적용 전(off)과 적용 후(on)를 60초씩 번갈아 측정한 원자료와 분석 스크립트입니다.

| 폴더 | 측정 시각 | 회차 | 결과 |
|---|---|---|---|
| [`20261118-1`](20261118-1) | 2026-11-18 16:44~17:12 | off 10 · on 10 | [RESULTS.md](20261118-1/RESULTS.md) |
| [`20261118-2`](20261118-2) | 2026-11-18 17:42~18:03 | off 8 · on 7 | [RESULTS.md](20261118-2/RESULTS.md) |

- 공통 환경: 마비노기 클라이언트(`Client.exe`, D3D9), 논리 프로세서 4개(코어 2개 × 스레드 2개).
- `20261118-1`은 [성능 측정 보고서(PDF)](../docs/performance-report-2026-11-18.pdf)의 원자료입니다.
- 각 폴더의 `presentmon/`에는 PresentMon CSV, `logs/`에는 on 회차 직전에 실행한 GameOptimizer 진단 로그가 있습니다.
- 진단 로그 첫 줄에 빌드 정보가 없으므로, 빌드 정보 기록이 추가된 `a9b9644` 이전 코드로 만든 실행 파일입니다. 그 뒤의 엔진 변경은 로그의 소수점 자릿수뿐이라, 코어 선정 동작은 현재 코드와 같습니다.

## 다시 계산하기

```powershell
pip install numpy pandas scipy
python measurements/analyze.py measurements/20261118-1
```

결과는 화면에 출력되고, 같은 내용이 해당 폴더의 `RESULTS.md`로 저장됩니다.

## 계산 방식

- **off/on 구분:** 직전 CSV 시작과 해당 CSV 시작 사이에 진단 로그가 시작됐으면 on입니다.
- **지표:** 프레임타임은 `MsBetweenPresents`를 씁니다.
  - 평균 FPS = 1000 ÷ 평균 프레임타임
  - p99 = 프레임타임 99백분위수
  - 1% low = 가장 느린 1% 프레임의 평균 프레임타임을 FPS로 환산
  - 프레임 간 변동 = 연속한 두 프레임타임 차이(절댓값)의 평균
  - CPU·GPU Busy = `MsCPUBusy`, `MsGPUBusy`의 평균
- **검정:** 인접한 off→on 쌍의 차이(on − off)로 Wilcoxon 부호순위 검정(정확 검정)을 하고, 부트스트랩 20,000회(시드 고정)로 95% 신뢰구간을 구합니다. 지표 7개에 Bonferroni 보정을 적용합니다(p<0.0071).
- **순서 효과 점검:** 같은 데이터를 on→off 쌍으로 다시 묶어 평균 FPS 차이를 비교합니다. 두 방향의 결과가 같으면, 시간이 지나면서 생긴 변화보다 적용 여부가 차이를 만든 것으로 볼 수 있습니다.

PDF 보고서와 다른 점:
- 보고서는 지표 18개 기준으로 Bonferroni 보정을 했습니다(p<0.0028). 보정 후 유의한 지표는 두 기준에서 같습니다.
- 1% low FPS는 경계 프레임을 세는 방식 때문에 보고서 값과 0.2 FPS 정도 차이가 납니다(보고서 58.8 → 57.2, 스크립트 59.0 → 57.4).
